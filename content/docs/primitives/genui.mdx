## Usage guidelines

- **Experimental** — the entries may change in any minor release while the API settles. Pin an exact version, and check the changelog when upgrading.
- **Three entries** — `@intentface/chat/genui` is the headless core: the catalog, its zod schemas, spec checks, streaming reads, bindings, render props, the tool helper and Markdown. It imports no React and touches no DOM, so a server can validate, store and index specs with it. `@intentface/chat/genui-render` draws them, and `@intentface/chat/genui-testing` checks your components.
- **Bring your own components** — the package works out the logic of every piece and hands your components *render props*: values formatted, alignment and tone decided. Your components own markup, interaction and styling. Nothing the package ships is styled, so a stored spec re-skins itself when your theme changes: it never held a colour.
- **Two tiers** — a *spec* is a layout the model composes from elements (`Card`, `Grid`, `Metric`…). A *view* is a precomposed piece it picks and fills (`table`, `email`…). Offer either or both.
- **Every entry reads as Markdown** — `toMarkdown` is required on every catalog entry. It is what the UI turns into in a clipboard, a model's history, a search index, a document an agent reads later, and on screen for a piece your map has no component for.
- **One Root per UI** — how far the input has got and what the reader did to it belong to one tool call, so render a `GenUi.Root` for each.
- **Not tied to a chat** — the renderer reads no thread or message context. Mount it in a reply, a document node, a slide or a read-only share.
- **No AI SDK dependency** — the tool helper hands you a description, a JSON schema and validation; wrap them with whichever SDK you use. `zod` 4 is a peer dependency.
- **Get started** — see [Quick start](/quick-start) to add the package.

## Anatomy

```tsx
import { GenUi } from "@intentface/chat/genui-render";

<GenUi.Root components={components} phase="accepted">
  <GenUi.Part>                  {/* optional: copying takes the whole UI */}
    <GenUi.Spec input={spec} /> {/* a layout */}
    {/* or <GenUi.View input={view} /> */}
  </GenUi.Part>
</GenUi.Root>
```

`GenUi.Root` renders no element; it holds the catalog, the component map, the
phase and the reader's state. `GenUi.Spec` and `GenUi.View` render no wrapper
around what they draw either, so a `Grid`'s children are the grid's children.

## The catalog

`defaultCatalog` holds ten elements and six views:

| Elements | Views |
| --- | --- |
| `Card`, `Stack`, `Grid` (containers) | `table`, `chart`, `metrics` |
| `Heading`, `Text`, `Metric`, `KeyValue`, `DataTable`, `Chart`, `Callout` | `record`, `email`, `steps` |

Each entry is plain data: a `description` written for the model (*when* to use
it), zod `props`, an optional bindable `input` schema, `toMarkdown`, and a
realistic `example`. Optionally, `toRender` shapes its render props,
`summarise` describes it in a few words for a model's history, and `fixtures`
holds props in other states worth drawing. Extend or narrow a catalog by
spreading it into `defineCatalog`:

```ts
import {
  defaultCatalog,
  defineCatalog,
  defineElement,
  escapeMarkdownInline,
  formatValue,
} from "@intentface/chat/genui";

const Timeline = defineElement({
  description: "Dated events in order. For a history, not a plan.",
  container: false,
  props: z.object({ events: z.array(z.object({ date: z.string(), text: z.string() })) }),
  toMarkdown: (props) =>
    props.events
      .map((event) => `- ${escapeMarkdownInline(event.date)}: ${escapeMarkdownInline(event.text)}`)
      .join("\n"),
  // Pure: no React. Its component is drawn with what this returns.
  toRender: (props, { locale, timeZone }) => ({
    events: props.events.map((event) => ({
      date: formatValue(event.date, "date", undefined, { locale, timeZone }),
      text: event.text,
    })),
  }),
  example: { events: [{ date: "2026-10-01", text: "Signed" }] },
  fixtures: { empty: { events: [] } },
});

export const documents = defineCatalog({
  ...defaultCatalog,
  elements: { ...defaultCatalog.elements, Timeline },
  limits: { elements: 120, depth: 8 },
});
```

`limits` (40 elements, 6 deep and 24 children per container by default) are
what `checkSpec` enforces, and a single call can override them. The children cap
is also part of the schema the model is sent, built from the catalog, so a call
can lower it but only the catalog can raise it. The table row cap (500) is part
of that schema too, so it is set where the schema is built:
`createDefaultCatalog({ maxRows })`. That function also takes `refDescription`,
the one model-facing description only you can write: what your `$data` refs look
like.

## Render props

Schema props are shaped for the model: rows as arrays, raw numbers, no
handlers, because they cost output tokens. Your components get render props
instead, shaped for a design system, plus the schema props as `props` and, for
a container, its drawn `children`:

| Entry | Render props |
| --- | --- |
| `Card`, `Stack`, `Grid`, `Heading`, `Text`, `Callout`, `email` | The schema props |
| `Metric` | `label`, `text` (formatted), `delta?: { text, label?, direction, tone }`, `tone` |
| `KeyValue` | `items: { label, value, text }[]` |
| `DataTable`, `table` | `columns: { key, label, align, display, sortable, format? }[]`, `rows: { key, cells: { value, text }[] }[]`, `count` |
| `Chart`, `chart` | `kind`, `categories` (labels as shown), `series`, `stacked`, `formatValue(v)`, `formatTick(v)` |
| `metrics` | `items` of `Metric`'s render props |
| `record` | `name`, `subtitle?`, `status?: { label, tone }`, `fields`, `note?` |
| `steps` | `items: { key, title, detail?, status }[]` |

A view's component also gets its `title`. Values are formatted with Root's
`locale` and `timeZone`. Build the map with `defineComponents`, which checks it
against the catalog: an element without a component, or a component whose props
don't match its render props, is a type error.

```tsx
const components = defineComponents(catalog, {
  elements: {
    Metric: ({ label, text, delta }) => (
      <div>
        {label} <strong>{text}</strong> {delta?.text}
      </div>
    ),
    // …one per element
  },
});
```

Root reads against the widest catalog you know, so it takes any part of a map:
a piece without a component is drawn through `Fallback` from its Markdown.

## Specs

A spec is flat: `{ root, elements }`, with containers listing their children
by id. It comes in three forms:

| Form | Shape | Who uses it |
| --- | --- | --- |
| `SpecInputSchema` | Elements as a **list**, each naming its `id` | The model. Tool-schema converters turn a `z.record` into "an object with no properties", so the model is never shown the map. |
| `SpecSchema` | Elements **by id**, `v`, bindings in place | What you **store**. |
| `ResolvedSpecSchema` | The same, every bound value in place | What is drawn and written as Markdown. |

Get all three from `specSchemas(catalog)`. Call `canonicalSpec(input)` on model
input: it normalises the two slips models make (`component` written for `type`,
props written beside `type`), refuses duplicate ids, validates, checks the
tree, and stamps the catalog version. The errors come back in words a model
can act on, so they can be returned as the tool's answer.

```ts
const result = canonicalSpec(toolInput, { catalog });
if (!result.ok) return { ok: false, errors: result.errors };
await save(result.spec); // { v: 1, root, elements: { … } }
```

A view takes the same path through `canonicalView(input)`. It reads props
written beside `view`, refuses a view the catalog lacks (listing the ones it
has), validates the caption and the props, and stamps the catalog version:

```ts
const result = canonicalView(toolInput, { catalog });
if (!result.ok) return { ok: false, errors: result.errors };
await save(result.view); // { v: 1, view: "table", title?, props }
```

### Keeping specs

A spec can outlive the code that drew it by years. Never change an entry
incompatibly in place: add `ChartV2` beside `Chart`, or bump the catalog's
`version` and add a migration keyed by the version it migrates *from*.

```ts
const catalog = defineCatalog({
  ...base,
  version: 2,
  migrations: { 1: (spec) => renameType(spec, "Text", "Paragraph") },
});

const result = readStoredSpec(stored, { catalog }); // migrated, then validated
```

`readStoredSpec` reads a spec with no `v` as version 1. It refuses a spec from a
newer catalog rather than guessing at it, and parses strictly: the leniency
`canonicalSpec` gives model input never applies to something already stored.
`migrateSpec(spec, fromVersion, catalog)` runs only the migration steps.

`when` is reserved as an element-level key for conditions in a later catalog
version. Until then, it is refused by name rather than read as a prop, and an
element that carries it is left out of what is drawn: shown without its
condition, it could reveal what was meant to be hidden.

## The tool helper

`genUiTool(catalog, options)` gives a host everything a generative-UI tool
needs, with no SDK in it: a description that tells the model when to use UI and
the rules a call keeps, the JSON schema it is shown, an example, validation
with a summary, and what to tell the model afterwards. The schema is shown but
not enforced by the SDK: `accept` validates, so a refusal names the field and
the model can fix it.

```ts
import { genUiTool } from "@intentface/chat/genui";
import { jsonSchema, tool } from "ai";

const layout = genUiTool(catalog, { name: "show_ui", kind: "spec" });

export const showUi = tool({
  description: layout.description,
  inputSchema: jsonSchema(layout.inputSchema),
  execute: async (input) => {
    const result = layout.accept(input);
    if (result.ok) await save(result.spec);
    return layout.modelText(result); // "Shown to the user: …" or what to fix
  },
});
```

A view tool takes `kind: "view"` and, optionally, the `views` it offers; its
schema is `{ view, title?, props }`, an object at the top as providers require.
The helper is built once per catalog and options, so the definition stays
stable for a provider's prompt cache. Before sending history back to the
model, `compactHistory(messages, { tools })` replaces earlier large UI inputs
with what they showed.

## Data by reference

A table's rows, or a chart's categories and series, can name their data instead
of copying it:

```json
{ "$data": "queries/paid-by-branch", "columns": ["branch", "paid"] }
```

The ref is an **opaque string**. No schema here constrains its format, and
nothing here resolves it. A chat might resolve it against a tool result and a
document against a saved query. You resolve each binding and file the values
by where the binding sits (`elements.paid.props.rows`); then `withData`, the
renderer's `data` prop or the export's `data` option swaps them in.

## UI state

What the reader does to a drawn UI (the open tab, the ticked items, the sort)
is kept beside the spec, never in it: an accepted spec is immutable. Root holds
it uncontrolled from `defaultState`, or controlled through `state` and
`onStateChange`. A change carries the package's change details, and
`details.cancel()` keeps it from landing.

```tsx
<GenUi.Root
  components={components}
  state={state}
  onStateChange={(next) => save(callId, persistedState(next))}
>
  <GenUi.Spec input={spec} />
</GenUi.Root>
```

`persistedState` keeps what outlives the session (open tabs and disclosures,
ticked items) and drops the sort, page and search. `readState(input, stored)`
reads stored state back against its spec, dropping pieces that have gone and
fields of the wrong type. A read-only share passes nothing and persists
nothing.

## Markdown

The same spec, on screen and as Markdown. Its table's rows are bound with
`$data`, so switch to "Not loaded yet" to see what a reader gets before the
host has fetched them: a line saying where the data lives, never a gap.

<Demo component={<MarkdownExport />} file="primitives/genui/demos/markdown.tsx" />

`toMarkdown(spec, options)` and `viewToMarkdown(view, options)` walk the input
in reading order. Each entry's `toMarkdown(props, { children, title, state,
locale, timeZone })` decides how it reads. `exportSpec` and `exportView` return
the same Markdown plus every table as raw rows (`toCsv`, `toTsv`), named by the
heading before it or the card it sits in.

- **Literal text** — whatever the model wrote or a source returned reads as written: nothing in it can format, link, or break the structure around it, and a bare address is not turned into a link. Links come only from you. A custom entry escapes its text the same way, with `escapeMarkdown`, `escapeMarkdownInline` and `markdownHeading`. The `email` view is the exception: it stays plain text for pasting into a mail client.
- **`state`** — the reader's UI state, so the Markdown follows what they did.
- **`locale`, `timeZone`** — both default to the runtime's. Pass both on a server: stored Markdown must not change with the host that wrote it. A calendar date (`2026-11-30`) is always read in UTC, so it never becomes the evening before; `timeZone` applies to timestamps.
- **`onUnbound`** — what a piece reads as when its data is bound and wasn't resolved. The default is `null`, which leaves the piece out. That suits copying from a chat, where the reader saw what was drawn. A document should return a line saying where the data lives: an agent reading a gap later would take it to mean there is no data.

## Copying

Copying never loses a UI. A message's copy action reads each part with
`partToMarkdown(part, { tools, state })`: text as written, each UI as its
Markdown at the reader's state. For a selection, wrap each UI in `GenUi.Part`
and put `copyWithGenUi` on the container's `onCopy`. A selection that touches a
UI copies that UI's whole Markdown in place of its on-screen text, since half a
table isn't meaningful Markdown; any other selection copies as the browser
always does.

```tsx
<div onCopy={copyWithGenUi}>
  <p>{text}</p>
  <GenUi.Root components={components}>
    <GenUi.Part>
      <GenUi.Spec input={spec} />
    </GenUi.Part>
  </GenUi.Root>
</div>
```

## Streaming

<Demo component={<Streaming />} file="primitives/genui/demos/streaming.tsx" />

Tool input streams as half-written JSON. Pass it as it is, with
`phase="streaming"` until it is whole, `"complete"` once it is, and
`"accepted"` once `canonicalSpec` or `canonicalView` has passed it:

- **Only what parses is drawn.** An element whose type isn't known yet is skipped, and one whose props don't parse yet is `Pending`. A container still pending keeps its children on screen.
- **Steady.** Streamed JSON goes valid, invalid, valid again many times a second: an enum caught mid-word fails for one chunk. Each piece keeps the last props that parsed until newer ones do, so it never blinks back. `useSteady` is exported for your own pieces.
- **Settled.** An entry with long arrays can define `settle` to drop the row still being written, rather than draw it short.
- **Live.** With `live`, each piece goes through `Arrive` as it lands. Decide it once, at mount: a spec reopened from history should draw still.

Once whole, a piece that still doesn't parse is dropped, or drawn by
`Unbound` when the reason is unresolved data. A piece that throws while
rendering is dropped by its own error boundary and reported to `onError`; the
rest of the spec still draws.

## Testing

`@intentface/chat/genui-testing` checks a component map against what its
render props promise. `checkComponents` draws every fixture of the catalog
(each piece's example, its own `fixtures`, and mid-stream) through your map in
a real DOM, and returns what fails as strings, so it works under any test
runner:

```ts
import { checkComponents } from "@intentface/chat/genui-testing";

test("our components draw every piece", async () => {
  expect(await checkComponents(components, { catalog })).toEqual([]);
});
```

It checks what a reader gets, not markup: every text the render props carry is
on screen, a table has its header and row roles, a heading has the heading
role, a container draws its children, and no piece throws. `fixtures(catalog)`
hands the same inputs to your own stories. It needs a DOM (happy-dom, jsdom)
and `@testing-library/dom`.

### Hooks and helpers

- `defineComponents(catalog, map)` — the map, checked against the catalog.
- `copyWithGenUi(event)` — a copy handler that takes each touched UI's whole Markdown.
- `useGenUiElement()` — the piece being drawn: `{ id, type }` for an element, `{ type }` for a view. Use it to look a piece up in state you keep beside the spec, without adding that state to its props.
- `useGenUiLive()` — whether the input is live.
- `useSteady(value)` — the newest defined value, held across renders. Compared by identity, so pass a memoised value.
