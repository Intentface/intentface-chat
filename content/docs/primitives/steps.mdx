---
title: Steps
description: A collapsible timeline of a run — reasoning, tool calls, and answered questions as chronological steps.
---

Steps is a recursive disclosure tree: every node is an `Item` with a `Trigger`
and a `Panel`, and panels can contain further items, so timelines nest
arbitrarily. Nested items surface `data-nested` for rail styling; sibling
facts (the last connector) are plain CSS. Row helpers ship as named exports —
`StepsStep` is the high-level row (label, status, icon), and `StepsToolCall` /
`StepsAskUser` derive a label, status, and summary from a tool part, so you
pass the part and they render the row.

## Anatomy

The bare nesting — a timeline is a top-level item whose panel holds the rows:

```tsx
<Steps>
  <Steps.Item>
    <Steps.Trigger>Steps</Steps.Trigger>
    <Steps.Panel>
      <StepsStep label="Read the request" status="complete" />
    </Steps.Panel>
  </Steps.Item>
</Steps>
```

Driven from message segments — tool parts render themselves:

```tsx
<Steps>
  <Steps.Item defaultOpen={isStreaming}>
    <Steps.Trigger>{header}</Steps.Trigger>
    <Steps.Panel>
      {segments.map((seg) =>
        seg.type === "reasoning" ? (
          <StepsStep label={seg.header} status="complete">
            <StepsBody>{seg.body}</StepsBody>
          </StepsStep>
        ) : seg.part.type === "tool-askUser" ? (
          <StepsAskUser part={seg.part} />
        ) : (
          <StepsToolCall part={seg.part} />
        ),
      )}
    </Steps.Panel>
  </Steps.Item>
</Steps>
```
