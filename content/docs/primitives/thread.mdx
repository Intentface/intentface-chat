Thread is the chat surface: a scroll container that lands the newest turn,
follows the stream while you're at the bottom, and yields the moment you scroll
up. It measures the composer dock to reserve space and exposes its scroll state
through `useThread`. It owns no message data — you map your messages into it.

## Anatomy

The bare nesting — `Thread` provides the scroll context its parts read:

```tsx
<Thread>
  <Thread.Viewport>{/* messages */}</Thread.Viewport>
  <Thread.Composer>{/* composer */}</Thread.Composer>
  <Thread.ScrollButton />
</Thread>
```

A realistic surface with overlays and a message list:

```tsx
<Thread autoScroll="follow">
  <Thread.Overlay direction="top" />
  <Thread.Viewport>
    {turns.map((turn) => (
      <Message.Turn key={turn.key}>{/* … */}</Message.Turn>
    ))}
  </Thread.Viewport>
  <Thread.Composer>
    <Composer onSubmit={sendMessage}>{/* … */}</Composer>
  </Thread.Composer>
  <Thread.ScrollButton />
</Thread>
```

## Auto-scroll

`autoScroll` controls how the newest turn lands and whether the view follows a
stream. `Thread.Viewport` maps `--thread-turn-min-height` onto its last child,
so the reserve that lets the newest turn land at the top is wired for you.

export const autoScrollProps = [
  { name: '"follow"', type: "default", description: "Newest lands at the top; the view follows the stream (ChatGPT-style)." },
  { name: '"bottom"', type: "", description: "Newest lands at the bottom; the view follows the stream (Codex-style)." },
  { name: '"jump"', type: "", description: "Newest lands at the top; the view does not follow." },
  { name: '"off"', type: "", description: "A plain scroll area — no landing, no follow, no reserve." },
];

<PropsTable rows={autoScrollProps} />

The follow is released by deliberate reading intent — a wheel, touch, or
scroll-key gesture, or dragging the scrollbar away from the bottom — and
re-arms when you return to the bottom. Content growth alone never releases it:
a large code block landing at once won't drop the follow mid-stream.

## useThread

Read the scroll state and issue commands from anywhere inside `<Thread>`:

export const useThreadMembers = [
  { name: "isAtBottom", type: "boolean", description: "Whether the bottom sentinel is in view. Subscribes the caller — only components that render it re-render on flips." },
  { name: "scrollToBottom", type: "(behavior?) => void", description: "Scroll to the live end." },
  { name: "scrollToTop", type: "(behavior?) => void", description: "Scroll to the start; releases the follow." },
  { name: "scrollToMessage", type: "(id, options?) => boolean", description: "Scroll to a row carrying data-message-id={id}. Options: align (\"start\" | \"center\" | \"end\" | \"nearest\"), behavior. Returns false when the id isn't mounted." },
];

<PropsTable rows={useThreadMembers} />

`scrollToMessage` resolves rows lazily by the `data-message-id` attribute — put
it on each row you want addressable; there is no wrapper component and no
per-row cost:

```tsx
{turns.map((turn) => (
  <Message.Turn key={turn.key} data-message-id={turn.id}>{/* … */}</Message.Turn>
))}
```

## Accessibility

The viewport is a focusable `role="region"` (default `aria-label="Messages"`,
overridable), so keyboard users can Tab to it and scroll with the arrow and
page keys. The content column is a `role="log"` announcing additions.
